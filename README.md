# 月图 · MoonAtlas

把散落的 Markdown / TXT 资料整理成可追溯、可持续更新的知识地图。

面向维护文档的同学、团队知识库负责人和个人笔记使用者。导入整个资料夹，
先看主题与文档，再展开标题、查看带行号的原文；把你的分类判断保存下来，
下一次更新资料时继续使用。

**网页应用：1.0.0 正式版。Mooncakes 核心库：icyaaaww/moonatlas@0.1.0，已发布并验证安装。尚无真实用户验证结果。**

[GitHub 仓库](https://github.com/icyaaaww/moonatlas) · [离线使用包](https://github.com/icyaaaww/moonatlas/releases/latest) · [验证记录](docs/validation.md)

## 直接使用

从 [1.0 正式版发布页](https://github.com/icyaaaww/moonatlas/releases/tag/v1.0.0) 下载 `MoonAtlas-1.0.0-offline.zip`，解压并双击其中的 `MoonAtlas.html`。
源码包、升级说明和试用任务随版本提供；旧版本仍保留在发布历史中。
不需要安装 Node、MoonBit，不需要账号、服务器或 API Key。浏览器实测范围见 [验证记录](docs/validation.md)。

1. 首页选择“导入自己的资料”“继续上次整理”或“体验示例”。示例中的 8 篇文档均为虚构，不会自动混入自己的资料。
2. 点击“导入文件夹”保留目录与相对链接，或多选 `.md` / `.txt`；先核对预览，再确认导入。
3. 搜索正文关键词，点击结果直接跳到地图节点与准确原文行；在右侧设置主题、显示名称，也可批量分类。
4. 点击“保存项目”下载 JSON，再从“备份与恢复”选回文件验证。恢复时打开项目 JSON，可找回原文、分类、归并规则、处理记录和基线。
5. 更新资料时，在预览中选择“合并新增 / 更新”或“以本次文件替换资料集”。确认移出名单后应用，再到“更新记录”核对变化。

默认只在内存中保留项目。点击顶部“本机自动保存”并主动开启后，整理会自动写入当前浏览器草稿。
重新打开同一地址时可选择恢复；也可关闭保存或清除草稿。未开启时请下载项目并选回验证后再关闭页面。
草稿可能随浏览器清理、无痕窗口结束或应用地址改变而无法恢复，**建议定期下载 JSON 备份**。
所有整理操作只改变当前项目，**不会写回或删除原始文件**。

## 1.0 新增：完成一次可靠的整理闭环

- **开始页面**：区分自己的资料、已有项目和虚构示例；导入后提示搜索、体检、备份三步。
- **导入预览**：先显示新增、覆盖修改、移出、重命名、未变和跳过文件。读取可取消，导入可一步撤销；无效文件不会部分写入当前项目。
- **搜索到出处**：MoonBit 搜索标题、路径、主题、标签和原文；显示命中片段与行号，点击展开对应地图节点并高亮原文。关键词最多 200 个 UTF-16 码元，最多展示 200 条结果，每页 10 条，并显示总命中数。
- **批量整理**：给多篇文档设置共同主题；批量标记体检项已处理或忽略，忽略必须填原因。确认前列出影响范围，一次操作可一步撤销。
- **备份与恢复**：新 JSON 带 SHA-256 校验值；下载仅标记“待验证”，选回后确认可重建且与当前资料一致才标记已备份。损坏文件或另一份项目不会覆盖当前工作。
- **兼容旧项目**：继续接受 0.1–0.3 的 v1 JSON；无校验值的旧文件会明确提示。升级流程见 [1.0 使用与迁移指南](docs/upgrade-1.0.md)。

校验值用于检测意外修改或损坏，不证明备份来源，也不是加密。仅保存一份本机草稿；多个知识库请分别保存项目 JSON。
性能测量方法及结果见 [性能记录](docs/performance.md)。

## 0.3 已有：从发现问题到完成整理

- **知识库体检**：统一列出待分类、完全相同内容及异常引用；按类型、待处理/已处理/已忽略筛选，每页最多 30 项。
- **处理记录**：记录备注，忽略必须填写原因；记录随项目 JSON、本机草稿和分享 HTML 保存，支持撤销/重做。已处理表示人工核对，不代表源文档已修正。
- **更新后再核对**：重新导入时，来源原文变化会使仍可识别的任务重新待处理，并保留备注。问题消失后移除对应记录；引用位置或目标改变可能生成新任务。
- **更新影响追踪**：同时检查基线和当前快照，列出指向变化文档的直接引用。删除和改名也可回到基线的准确引用行，不把引用关系当作内容错误。
- **行级变化高亮**：章节对照标记删除/新增行，提供上一处、下一处和跨页定位；大变化区域显式降级为整段标记，原文保持完整。
- **整理报告**：导出 Markdown，包含当前问题、人工备注及引用位置，不包含正文。

点击侧栏“体验整理与更新”，可以使用虚构团队资料走完这条流程。
使用指南见 [升级到 0.3](docs/upgrade-0.3.md)。旧 v1 项目仍可打开；新增可选 `reviews` 字段，旧应用重新保存可能丢失处理记录。

## 0.2 新增

- **本机自动保存**：保存原文、分类、规则与基线。写入成功才显示“已保存”；空间不足或多窗口冲突时暂停并提示。
- **撤销 / 重做**：覆盖分类、归并、导入更新、移出文档和基线调整。当前窗口最多 20 步，缓存最多 16,000,000 个 JSON UTF-16 码元；较大项目可保留的步数更少。切换项目或刷新会清空历史。
- **地图导航**：缩放、适合宽度、拖动空白处或方向键平移、主题折叠和聚焦。Ctrl/⌘ + 滚轮缩放。
- **引用连线**：虚线表示资料内真实存在的文档引用，点击可定位来源行；同屏最多 60 条，可关闭以保持清晰。它不是语义关联推断。
- **章节级更新**：在“更新记录”打开变化文档，并排查看章节修改前后原文；支持新增、移除、长章节分页及当前原文定位。地图同时标记有变化的文档。

项目文件格式仍为 v1，可以继续打开 0.1 导出的 JSON。快捷键：Ctrl/⌘ + Z 撤销，Ctrl/⌘ + Shift + Z 或 Ctrl/⌘ + Y 重做；输入框内保留原生文本撤销。
只保存一份当前草稿；切换资料集前会提示备份。撤销历史、自动保存开关与草稿版本号不会写进项目/分享文件。

## 已实现

| 能力 | 实际行为 |
| --- | --- |
| 全局知识地图 | 主题 → 文档 → 可展开的原文标题；支持全文搜索、缩放平移、主题聚焦、显式引用连线 |
| 原文溯源 | 显示路径、行号、完整原文；长文每页显示 100 行 |
| 跨文档线索 | 同名标题聚合；用户显式确认名称归并；保留所有出处 |
| 资料整理 | 待分类、内容完全相同的文件、缺失/歧义内部引用提示 |
| 稳定人工判断 | 分类、显示名称不因原文更新而丢失；唯一内容匹配重命名时迁移 |
| 更新对比 | 文件与章节变化、前后原文对照；可重设基线 |
| 导出 | SVG 总览、完整 Markdown 标题索引、图谱 JSON、可交互离线 HTML |
| 项目迁移 | 项目 JSON 保存及恢复，导入后重新构建图谱，不信任外部图谱数据 |

SVG 是主题与文档的总览；全部标题和原文可在交互 HTML 中查看。
项目 JSON、分享 HTML 含完整原文与旧基线，图谱 JSON 含摘录。请按资料权限选择分享范围。

## 三个完整使用场景

**团队文档交接。** 维护者导入工程手册目录，看到发布、复盘、演练文档之间的“回滚”线索；
点击来源核对各文档中的职责，给待整理资料设置主题，检查旧版链接是否仍存在；
导出交互 HTML 给接手者，接手者无需环境即可沿着地图找到原文。

**课程复习。** 学生导入数据库课程和阅读摘记，看到同名“查询计划”标题来自两篇资料；
核实后把 `B-tree` 归并为 `B树`，在同一个概念下并列查看不同来源；
导出 Markdown 索引用于复习，SVG 总览用于汇报。程序不会替学生断言两段内容含义相同。

**持续维护个人资料。** 用户保存已整理的项目和基线，下周导入一个完整新版目录；
系统指出新增、修改和移除，内容完全一致且匹配唯一的改名会延续分类；
用户核对更新后设为新基线，再次保存项目，避免每次重做分类。

## 实现边界

- 输入为 UTF-8 Markdown / TXT；不解析 PDF、Word、OCR，不直接读取飞书/Notion/Obsidian 服务。
  可以导入这些工具导出的 Markdown；不声称支持它们的全部扩展格式。
- Markdown 是明确受限的扫描器，不是完整 CommonMark/YAML：支持 ATX 标题、代码围栏、
  简单 `topic:` 与 `tags: [a, b]` 元数据、常见行内链接和 wiki links。
- 同名标题是词面线索。标签只展示，**没有大模型、向量搜索、语义聚类或自动事实核验**。
- 不支持的引用、附件和标题锚点会保留“未校验/不支持”的状态，外部网址不会被访问。
- 上限：200 篇文档，单篇 200,000 / 合计 2,000,000 UTF-16 码元，3,000 个标题，
  5,000 条引用，200 条分类规则和 200 条归并规则。超过上限显式拒绝，不静默截断图谱。
- 重命名依据为移除/新增集合中的唯一完全相同内容；同时改名并修改内容时按新增/移除处理。
- 尚未完成真实用户试用、无障碍专项审计、真实手机/Safari 设备验证和 Mooncakes 发布；不承诺所有浏览器都兼容。

## 开发与复现

需要 MoonBit 工具链和 Node.js 22 以上版本。已验证版本见 `docs/validation.md`。
从仓库根目录执行：

```sh
npm ci
moon update
moon check --target all
moon test --target js
moon test --target wasm-gc
npm run build
npm test
npx playwright install chromium
npm run test:browser
# 其他引擎回归（需安装相应浏览器）
npx playwright install firefox webkit
npm run test:compat
# 可复现的合成资料性能测量
node scripts/measure-workspace.mjs
```

构建生成 `web/core.mjs` 和 `dist/MoonAtlas.html`。可直接打开后者，或执行 `npm start`
使用仅绑定本机 `127.0.0.1:4173` 的开发服务器；它只提供固定静态资源，没有上传或写文件接口。

MoonBit 库示例：

```sh
moon run examples/demo --target js
```

MoonBit 核心库已发布到 Mooncakes，可在其他 MoonBit 项目中安装：

```sh
moon add icyaaaww/moonatlas
```

公开 API 示例与导入方式见 `README.mbt.md`，实际安装验证见 [Mooncakes 发布记录](docs/mooncakes-release.md)。
当前包版本为 `0.1.0`，对应网页应用 `1.0.0` 的核心能力；两者独立编号。当前发布工具要求包版本使用 `0.x.y`。

## 项目结构

```text
model.mbt / parser.mbt     数据契约、输入边界与原文标题解析
atlas.mbt / links.mbt      概念归并、证据、引用与相同内容检测
changes.mbt / svg.mbt      版本比较、人工选择迁移和导出
section_changes.mbt       完整章节文本比较与两侧证据
maintenance.mbt           结构体检任务与双快照直接引用追踪
line_diff.mbt              有资源边界的行差异范围计算
workspace.mbt              有出处的搜索与原子批量分类
bridge/                   JSON 传输接口
examples/demo/            MoonBit 库使用示例
web/                      本地文件交互、展示与项目文件
host/                     固定路由的本机开发服务器
tests/                    Node 与多浏览器流程测试
scripts/build.mbtx        MoonBit 构建与离线 HTML 打包
docs/                     架构、验证、生态比较及试用任务
```

图谱判断、解析、概念规则、版本对比和导出算法由 MoonBit 实现；JavaScript 负责浏览器文件接口与界面。
Apache-2.0。依赖和参考说明见 `docs/provenance.md`。比赛准备情况见 `docs/competition-notes.md`。
