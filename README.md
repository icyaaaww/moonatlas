# 月图 · MoonAtlas

把散落的 Markdown / TXT 资料整理成可追溯、可持续更新的知识地图。

面向维护文档的同学、团队知识库负责人和个人笔记使用者。导入整个资料夹，
先看主题与文档，再展开标题、查看带行号的原文；把你的分类判断保存下来，
下一次更新资料时继续使用。

**当前状态：0.1.0 本地可用版本。尚未发布 GitHub / Mooncakes，尚无真实用户验证结果。**

## 直接使用

双击交付包中的 `MoonAtlas.html`，使用现代 Chrome / Edge / Firefox 浏览器打开。
不需要安装 Node、MoonBit，不需要账号、服务器或 API Key。当前实测浏览器为 Chromium。

1. 先探索内置的 8 篇**虚构示例资料**。展开“发布流程”，点击“回滚”，查看右侧出处。
2. 点击“导入文件夹”保留目录与相对链接，或多选导入 `.md` / `.txt`。
3. 在右侧设置主题、显示名称；在“跨文档线索”中确认概念名称归并。
4. 点击“保存项目”下载 JSON。下一次用“打开项目文件”恢复原文、分类、归并规则和基线。
5. 更新资料时选择“合并新增 / 更新”或“以本次文件替换资料集”，在“更新记录”中核对变化。

窗口默认只在内存中保留项目，**没有自动保存**。请确认下载成功后再关闭页面。
所有整理操作只改变当前项目，**不会写回或删除原始文件**。

## 已实现

| 能力 | 实际行为 |
| --- | --- |
| 全局知识地图 | 主题 → 文档 → 可展开的原文标题；支持全文搜索 |
| 原文溯源 | 显示路径、行号、完整原文；长文每页显示 100 行 |
| 跨文档线索 | 同名标题聚合；用户显式确认名称归并；保留所有出处 |
| 资料整理 | 待分类、内容完全相同的文件、缺失/歧义内部引用提示 |
| 稳定人工判断 | 分类、显示名称不因原文更新而丢失；唯一内容匹配重命名时迁移 |
| 更新对比 | 与用户基线比较新增、修改、移除、重命名；可重设基线 |
| 导出 | SVG 总览、完整 Markdown 标题索引、图谱 JSON、可交互离线 HTML |
| 项目迁移 | 项目 JSON 保存及恢复，导入后重新构建图谱，不信任外部图谱数据 |

SVG 是主题与文档的总览；全部标题和原文可在交互 HTML 中查看。
项目 JSON、分享 HTML 含完整原文与旧基线，图谱 JSON 含摘录。请按资料权限选择分享范围。

## 三个完整使用场景

**团队文档交接。** 维护者导入工程手册目录，看到发布、复盘、演练文档之间的“回滚”线索；
点击来源核对各文档中的职责，给待整理资料设置主题，检查旧版链接是否仍存在；
导出交互 HTML 给接手者，接手者无需环境即可沿着地图找到原文。

**课程复习。** 学生导入数据库课程和阅读摘记，看到同名“查询计划”标题来自两篇资料；
核实后把 `B-tree` 归并为 `B树`，在同一个概念下并列查看不同来源；
导出 Markdown 索引用于复习，SVG 总览用于汇报。程序不会替学生断言两段内容含义相同。

**持续维护个人资料。** 用户保存已整理的项目和基线，下周导入一个完整新版目录；
系统指出新增、修改和移除，内容完全一致且匹配唯一的改名会延续分类；
用户核对更新后设为新基线，再次保存项目，避免每次重做分类。

## 实现边界

- 输入为 UTF-8 Markdown / TXT；不解析 PDF、Word、OCR，不直接读取飞书/Notion/Obsidian 服务。
  可以导入这些工具导出的 Markdown；不声称支持它们的全部扩展格式。
- Markdown 是明确受限的扫描器，不是完整 CommonMark/YAML：支持 ATX 标题、代码围栏、
  简单 `topic:` 与 `tags: [a, b]` 元数据、常见行内链接和 wiki links。
- 同名标题是词面线索。标签只展示，**没有大模型、向量搜索、语义聚类或自动事实核验**。
- 不支持的引用、附件和标题锚点会保留“未校验/不支持”的状态，外部网址不会被访问。
- 上限：200 篇文档，单篇 200,000 / 合计 2,000,000 UTF-16 码元，3,000 个标题，
  5,000 条引用，200 条分类规则和 200 条归并规则。超过上限显式拒绝，不静默截断图谱。
- 重命名依据为移除/新增集合中的唯一完全相同内容；同时改名并修改内容时按新增/移除处理。
- 尚未完成真实用户试用、无障碍专项审计、全浏览器兼容性验证和 Mooncakes 发布。

## 开发与复现

需要 MoonBit 工具链和 Node.js 22 以上版本。已验证版本见 `docs/validation.md`。
从仓库根目录执行：

```sh
npm ci
moon check --target all
moon test --target js
moon test --target wasm-gc
npm run build
npm test
npx playwright install chromium
npm run test:browser
```

构建生成 `web/core.mjs` 和 `dist/MoonAtlas.html`。可直接打开后者，或执行 `npm start`
使用仅绑定本机 `127.0.0.1:4173` 的开发服务器；它只提供固定静态资源，没有上传或写文件接口。

MoonBit 库示例：

```sh
moon run examples/demo --target js
```

公开 API 示例见 `README.mbt.md`。包尚未发布，暂不要执行 `moon add icyaaaww/moonatlas`。

## 项目结构

```text
model.mbt / parser.mbt     数据契约、输入边界与原文标题解析
atlas.mbt / links.mbt      概念归并、证据、引用与相同内容检测
changes.mbt / svg.mbt      版本比较、人工选择迁移和导出
bridge/                   JSON 传输接口
examples/demo/            MoonBit 库使用示例
web/                      本地文件交互、展示与项目文件
host/                     固定路由的本机开发服务器
tests/                    Node 与 Chromium 集成测试
scripts/build.mbtx        MoonBit 构建与离线 HTML 打包
docs/                     架构、验证、生态比较及试用任务
```

图谱判断、解析、概念规则、版本对比和导出算法由 MoonBit 实现；JavaScript 负责浏览器文件接口与界面。
Apache-2.0。依赖和参考说明见 `docs/provenance.md`。比赛准备情况见 `docs/competition-notes.md`。
