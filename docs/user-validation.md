# 真实用户试用任务包

状态：准备完成，**尚未开展真实用户试用**。自动化测试不能替代下面的用户证据。

优先邀请 3–5 位维护 Markdown 文档或知识库的同学/同事。
由使用者自选可以在本机打开的资料；反馈只收集计时、任务完成情况和体验描述，默认不收集原文。

| 任务 | 观察点 | 成功标准 |
| --- | --- | --- |
| 导入自己的 20–100 篇资料，找出一篇文档所属主题 | 能否理解导入和目录关系，耗时多久 | 无帮助完成，并说出原文路径 |
| 从跨文档线索打开两份来源，判断是否应归并 | 是否把同名标题误以为事实结论 | 能解释各自上下文，明确确认或拒绝归并 |
| 修正三篇文档分类，保存后关闭并恢复项目 | 是否理解需要下载保存 | 重开后分类、原文、规则全部保留 |
| 更新一个文件、改名一个文件、移除一个文件 | 能否选择合并与完整替换，是否理解基线 | 与事先记录的变化一致；确认改名后分类延续 |
| 导出 HTML 分享给另一位同事离线打开 | 导出是否符合资料权限，接收者能否使用 | 断网可展开标题并定位原文 |
| 开启本机自动保存，关闭重开后恢复；再清除草稿 | 能否区分本机草稿与下载备份 | 恢复后内容完整；清除后不自动恢复 |
| 修改分类、移出文档后撤销/重做 | 是否理解撤销只在当前窗口保留 | 状态准确回到操作前后，原始文件未变化 |
| 聚焦一个主题，沿引用连线找出处 | 缩放、平移是否易用，是否误解连线含义 | 能找到引用来源行并辨认显式引用 |
| 更新一段正文，对比前后章节 | 是否能快速辨认修改位置，长文分页是否清楚 | 指出真实修改内容；不把标题配对当语义判定 |

建议记录：匿名试用编号、资料数量/格式、任务起止时间、是否独立完成、误点击/误解、最常见问题、愿不愿继续用及原因。
不要编写不存在的好评、节省时间百分比或活跃用户数。

## 对照方式

同一位用户分别使用现有文件夹/编辑器和 MoonAtlas 完成“找到两个相关出处、确认更新影响”的任务。
交替两种工具的顺序，尽可能使用难度接近的资料集。保留原始时间与失败记录，样本量小只报告个体结果。

## 0.3 首轮试用：20 分钟维护任务

这一轮尚未执行；以下是给 3–5 位维护知识库的同学/同事的任务，不是已取得的反馈。
先用包内虚构示例熟悉入口，再用本人允许在本机处理的 20–100 篇文档验证实际适用性。

| 任务 | 记录与核验 |
| --- | --- |
| 找到一个体检项，打开原文，判断如何处理 | 耗时、是否独立完成、是否理解缺失可能是未导入 |
| 标记已处理或写原因忽略，保存关闭后恢复 | 原文、状态、备注是否全部保留；是否误以为源文件已修改 |
| 更新来源原文后重新导入，检查任务状态 | 能否理解重新待处理和旧备注；不应认为旧判断永久有效 |
| 修改一篇被引用的文档，再删除另一篇被引用的文档 | 能否找到引用者，区分基线/当前位置；是否误以为系统判断了语义错误 |
| 在长章节中找到两处变化，导出整理报告 | 是否会用下一处变化；报告是否足够让同事继续核对 |

同时保留任务失败和不愿继续使用的原因。可与原有编辑器的搜索、文件对比方式交替顺序完成类似任务；小样本只报告个体结果。
未获得用户同意，不收集或公开原始文档。只汇总匿名任务完成情况、耗时及明确允许公开的反馈。
