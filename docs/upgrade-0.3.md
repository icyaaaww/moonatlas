# MoonAtlas 0.3 升级与使用指南

## 开始体验

解压 0.3 离线包，双击 `MoonAtlas.html`。无需账号或工具链。
点击侧栏“体验整理与更新”，载入一组虚构团队资料；也可用“打开项目文件”载入包内的 `整理与更新示例.json`。
手机端可通过示例项目 JSON 导入体验；侧栏示例按钮仅在较宽屏幕显示。

1. 打开“知识库体检”：检查未分类资料、相同内容和缺失的值班表引用。
2. 点击路径查看原文。核对后标记已处理，或填写原因后忽略；“已处理”仍会保留结构提示。
3. 保存项目，再次打开会恢复处理状态和备注。处理操作也支持撤销和本机草稿。
4. 打开“更新记录”：展开发布流程或已删除值班表的“需要核对的引用”。当前位置来自当前原文，基线位置来自旧快照，不能混为一谈。
5. 查看发布流程的章节变化，使用下一处变化或定位此处，查看高亮的旧行和新行。
6. 导出整理报告，记录当前检查结果和更新涉及的引用位置。

## 继续维护自己的资料

- 下载旧版项目 JSON 后，在 0.3 打开；0.1/0.2 的 v1 文件仍兼容。
- 新增可选 `reviews` 数组记录处理状态、备注和重新核对提示。旧应用可能忽略它，重新保存会丢失这些记录，建议保留原始备份。
- 浏览器草稿按应用路径隔离。换目录或换地址后，不保证能直接发现旧草稿，使用项目 JSON 迁移。
- 导入更新后的文档时，仍能识别的任务若来源原文变动，就重新待处理并保留备注。引用位置、目标或状态变化可能生成新任务。
- 问题修复后，对应记录从当前清单与保存文件移除；这是当前状态工作台，不是永久审计日志。需要归档时先导出报告。
- 最多保存 2,000 条人工记录，总记录文本最多 1,000,000 个 UTF-16 码元，单条备注最多 1,000 个码元；超限会明确拒绝本次操作。

## 判断边界

处理记录不是自动修复，也不会写回源文件。未导入的目标可能被提示为缺失。
影响追踪只核对可解析的直接引用；两个快照可能分别列出同一引用，不表示有两个独立来源。
没有引用结果，不代表没有业务或知识依赖。锚点仍不验证。
行差异比较保留换行和字符差别；较大变化区域会明确按整段标记，不截断原文。
整理报告不包含正文，但包含路径、目标及人工备注；项目文件和分享 HTML 仍包含完整原文及基线。
